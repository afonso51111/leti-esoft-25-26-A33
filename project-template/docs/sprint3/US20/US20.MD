# US20 - Register a Receptionist

## 1. Requirements Engineering

### 1.1. User Story Description

As an Administrator, I want to register a receptionist.

### 1.2. Acceptance Criteria

* **AC1:** The Receptionist must have a valid Name, Address, Phone Number, Email, and Citizen Card Number.
* **AC2:** The email must be unique in the system.
* **AC3:** The system must generate a password/credentials for the new user.
* **AC4:** The Receptionist should be automatically assigned the "RECEPTIONIST" role in the system.

### 1.3. Found out Dependencies

* **US10:** Register an Employee (Generalization - since Receptionist is an Employee, they share base attributes).

### 1.4 Input and Output Data

**Input Data:**
* Typed data:
  * Name
  * Address
  * Phone Number
  * E-mail
  * Citizen Card Number

**Output Data:**
* Success message.
* Generated User Credentials (display or email).

## 3. Design

### 3.1. Realization of Functionality

The design follows the **Layered Architecture** using the **DTO** pattern to decouple the UI from the Domain.

1. **UI**: Collects the receptionist's data.
2. **Controller**: Receives the data via a `ReceptionistDTO` and delegates the task to the Service.
3. **Service**:
  * Validates business rules (e.g., checking for duplicate emails).
  * Uses a `ReceptionistMapper` to convert the DTO into a `Receptionist` domain object.
  * Calls the `ReceptionistRepository` to persist the object.
  * Integrates with the Authentication mechanism to register the login credentials.
4. **Repository**: Stores the `Receptionist` object.

| **Step 5** | ... saves the data? | `ReceptionistRepository` | **Repository**: Handles persistence. |
