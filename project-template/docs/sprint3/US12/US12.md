# US 12 - Get a list of all vaccines

## 1. Requirements Engineering

### 1.1. User Story Description

As DGS Administrator, I want to get a list of all vaccines.

### 1.2. Customer Specifications and Clarifications

**From the specifications document:**

> The Administrator intends to consult the list of registered vaccines in the system to manage the vaccination process.

**From the client clarifications:**

> **Question:** How should the list be presented?
>
> **Answer:** The vaccines should be presented grouped by their vaccine type. Within each type, they should be sorted alphabetically by brand.

### 1.3. Acceptance Criteria

- AC12-1: The vaccines should be grouped by vaccine type.
- AC12-2: Within each type, vaccines must be listed alphabetically by brand.
- AC12-3: If no vaccines exist, an empty list (or appropriate message) should be shown.

### 1.4. Found out Dependencies

- US11 ("Register a vaccine") is a dependency. This US (US12) lists the data created in US11.

### 1.5 Input and Output Data

**Input Data:**

- n/a (The user simply requests the list).

**Output Data:**

- List of registered vaccines (Name, Brand, Type).

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:--- |:--- |:--- |:--- |
| Step 1 | ... interacting with the actor? | ListVaccinesUI | Pure Fabrication: responsible for user interaction (View). |
| | ... coordinating the US? | ListVaccinesController | Controller: coordinates the use case logic. |
| Step 2 | ... requesting the list of vaccines? | ListVaccinesController | Controller: mediates between UI and the Data layer. |
| | ... knowing the VaccineStore? | Company | IE: The Company is the root entity that manages domain containers. |
| | ... owning the vaccine data? | VaccineStore | IE: Owns the collection (`List<Vaccine>`) of all registered vaccines. |
| | ... sorting and grouping the data? | VaccineStore | **Information Expert**: Since the Store contains the data, it is the most efficient place to apply the sorting logic (AC12-1) before returning the list. |
| Step 3 | ... returning the sorted list? | ListVaccinesController | Controller: passes the data from the domain to the UI. |
| Step 4 | ... displaying the list? | ListVaccinesUI | IE: responsible for presenting the information to the user. |

## 4. Tests

**Test 1:** Check that the list is empty when no vaccines are registered.

    TEST_F(VaccineStoreFixture, GetEmptyList){
        EXPECT_TRUE(this->store->getVaccines().empty());
    }

**Test 2:** Check that the list returns the correct number of vaccines.

    TEST_F(VaccineStoreFixture, GetAllVaccines){
        // Add 2 vaccines
        this->store->add(v1);
        this->store->add(v2);
        
        EXPECT_EQ(this->store->getVaccines().size(), 2);
    }

**Test 3:** Check that the vaccines are sorted by brand (AC12-1).

    TEST_F(VaccineStoreFixture, ListIsSortedByBrand){
        // Arrange: Insert "Pfizer" then "AstraZeneca" (Unsorted)
        auto v1 = container->create(L"Comirnaty", L"Pfizer", typeA);
        container->save(v1);
        auto v2 = container->create(L"Vaxzevria", L"AstraZeneca", typeA);
        container->save(v2);

        // Act
        auto list = container->getVaccines();
        
        // Assert: "AstraZeneca" should come before "Pfizer"
        EXPECT_EQ(list.front()->getBrand(), L"AstraZeneca");
    }

## 5. Construction (Implementation)

- The sorting logic was implemented using `std::sort` with a custom comparator lambda inside the `VaccineStore`.

## 7. Observations

- The decision to sort inside the `VaccineStore` ensures that any part of the application requesting the list gets it in the correct business order, respecting the Information Expert pattern.
