# US12 - Specify a new Vaccine Type

## 1. Requirements Engineering

### 1.1. User Story Description

As an Administrator, I want to specify a new vaccine type.

### 1.2. Acceptance Criteria

* **AC1:** The vaccine type code must be unique and have 5 alphanumeric characters.
* **AC2:** The description should not be empty.
* **AC3:** The technology must be specified (e.g., Live-attenuated, Inactivated, Subunit, Toxoid, mRNA, Viral Vector).

### 1.3. Found out Dependencies

* No dependencies found. This is a base entity for the system.

### 1.4 Input and Output Data

**Input Data:**
* Typed data:
    * Code (5 chars)
    * Short Description
    * Technology

**Output Data:**
* Success message.

## 3. Design

### 3.1. Realization of Functionality

The design follows the standard **Layered Architecture** (UI -> Controller -> Service -> Repository) using **DTOs** for data transfer.

1. **UI**: Collects Code, Description, and Technology.
2. **Controller**: Receives the DTO and delegates to the Service.
3. **Service**:
    * Checks if a Vaccine Type with the same code already exists in the Repository (Business Rule).
    * Uses the Mapper to create the `VaccineType` domain object.
    * Calls the Repository to save the object.
4. **Repository**: Persists the Vaccine Type.
