# US13 - Specify a new Vaccine

## 1. Requirements Engineering

### 1.1. User Story Description

As an Administrator, I want to specify a new vaccine and its administration process.

### 1.2. Acceptance Criteria

* **AC1:** The new vaccine must be associated with an existing Vaccine Type.
* **AC2:** The vaccine must have a unique identifier (Brand + Name combo or distinct ID).
* **AC3:** The administration process must define at least one age group.
* **AC4:** For each age group, the number of doses, dosage, and time interval between doses must be specified.

### 1.3. Found out Dependencies

* **US12:** Specify a new Vaccine Type (Vaccines depend on Types).

### 1.4 Input and Output Data

**Input Data:**
* Selected Data:
  * Vaccine Type
* Typed Data:
  * Name
  * Brand
  * Age Groups (Min, Max)
  * Doses per Group
  * Dosage per Dose
  * Time Interval between doses

**Output Data:**
* List of Vaccine Types.
* Success message.

## 3. Design

### 3.1. Realization of Functionality

The functionality is realized using a **Layered Architecture** with **Services** and **DTOs**.

1. **UI**: Requests the available Vaccine Types.
2. **Controller**: Calls the Service to get types and then to create the vaccine.
3. **Service**:
  * `VaccineService` retrieves `VaccineType` entities.
  * Maps the `VaccineDTO` (which contains nested administration data) into a `Vaccine` aggregate root.
  * Saves the `Vaccine` in the `VaccineRepository`.
4. **Repository**: Stores the aggregate.

### 3.2. Sequence Diagram (SD) Rationale

| Interaction ID | Question: Which class... | Answer | Justification (with Patterns) |
| :--- | :--- | :--- | :--- |
| **Step 1** | ... interacts with the actor? | `SpecifyVaccineUI` | **Pure Fabrication**: Handles user input. |
| **Step 2** | ... coordinates the operation? | `SpecifyVaccineController` | **Controller**: Bridges UI and Business Logic. |
| **Step 3** | ... implements business logic? | `VaccineService` | **Service Layer**: Manages domain objects and repositories. |
| **Step 4** | ... provides vaccine types? | `VaccineTypeRepository` | **Repository**: Access to VaccineType entities. |
| **Step 5** | ... creates the vaccine? | `VaccineMapper` / `Vaccine` | **Creator**: The Mapper assists in converting the DTO, but the Model enforces rules. |
| **Step 6** | ... persists the data? | `VaccineRepository` | **Repository**: Saves the new Vaccine. |
