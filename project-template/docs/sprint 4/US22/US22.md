# US22 - Register Arrival of an SNS User

## 1. Requirements Engineering

### 1.1. User Story Description

As Receptionist, I want to register the arrival of an SNS user at the vaccination center to take the vaccine.

### 1.2. Acceptance Criteria

* **AC1:** The system must validate if the SNS User has an appointment scheduled for the current day and current vaccination center.
* **AC2:** The system should not allow duplicate arrival registrations for the same appointment.
* **AC3:** Upon registration, the appointment status must change to "ARRIVED".
* **AC4:** The user must be added to the Waiting Room list.

### 1.3. Found out Dependencies

* **US21:** An appointment must exist to register an arrival.
* **US02:** The SNS User must be registered.
* **US09:** A Vaccination Center must exist.

### 1.4 Input and Output Data

**Input Data:**
* Typed data:
  * SNS User Number
* Selected data:
  * Confirmation of the appointment found.

**Output Data:**
* Display of appointment details (User Name, Date, Time, Vaccine Type).
* Success message.

## 3. Design

### 3.1. Realization of Functionality

The design follows the **Layered Architecture** with **Service Layer** and **DTO** pattern:

1. **UI**: Collects the SNS User Number.
2. **Controller**: Forwards the request to the `ArrivalService`.
3. **Service**:
  * Queries `AppointmentRepository` to find a valid appointment for "today".
  * Returns an `AppointmentDTO` to the UI for confirmation.
  * Upon confirmation, fetches the `VaccinationCenter` (and its `WaitingRoom`).
  * Creates an `Arrival` object and adds it to the `WaitingRoom`.
  * Updates the `Appointment` state to `ARRIVED`.
4. **Repository**: Used to abstract data access for Appointments and Centers.

### 3.2. Sequence Diagram (SD) Rationale

| Interaction ID | Question: Which class... | Answer | Justification (with Patterns) |
| :--- | :--- | :--- | :--- |
| **Step 1** | ... interacts with the actor? | `RegisterArrivalUI` | **Pure Fabrication**: Handles user I/O. |
| **Step 2** | ... coordinates the flow? | `RegisterArrivalController` | **Controller**: Delegates to the service. |
| **Step 3** | ... contains business logic? | `ArrivalService` | **Service Layer**: Orchestrates validation and state changes. |
| **Step 4** | ... finds the appointment? | `AppointmentRepository` | **Repository**: Abstraction for accessing Appointment aggregates. |
| **Step 5** | ... holds the waiting list? | `WaitingRoom` | **Information Expert**: The Waiting Room knows who is currently waiting. |
| **Step 6** | ... tracks the arrival? | `Arrival` | **Domain Model**: Represents the event of a user arriving. |
